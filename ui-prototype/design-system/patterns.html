2. The Moving Castle — Three Doors
Like Howl's castle with three different worlds behind three doors. Each represents a distinct mindset and capability within Kalcifer.
🔥
Hearth
Creative workshop. Flow building, ideation, canvas design, node manipulation, dry runs.
ბუხარი — where ideas become flows
⚔
Command
War room. Live instance monitoring, analytics, metrics, performance, segment overlap, audience insights.
მეთაური — where campaigns run
🌱
Grove
Garden. Results, learnings, growth metrics, harvest measurement, success rates, insights ripening.
კორომი — where growth is measured
Mental Model
Each door is a complete context shift. Navigation between them is top-level and intentional, not buried in sidebar. User can glimpse data from other doors (e.g., "Draft: 2 instances running") but must enter to interact deeply.
3. Navigation Patterns
How users move through Kalcifer: cross-page navigation, intra-page flow, and dynamic session management.
Cross-Page Navigation (Header)
Top-level navigation: Hearth → Command → Grove. Each is a complete view switch. Secondary nav within each door (Browse, Detail, Simulate, etc.) is local to that context.
<header class="main-nav"> <button class="nav-door" data-door="hearth">🔥 Hearth</button> <button class="nav-door" data-door="command">⚔ Command</button> <button class="nav-door" data-door="grove">🌱 Grove</button> </header>
Intra-Page Navigation (Sidebar)
Within a door, sidebar shows sessions, saved flows, or instances. Sessions are expandable. Quick-access chips below chat for suggestions and commands.
Sidebar + Chat Flow
  1. Session collapse: Sidebar shows list of sessions with icons (🔥 for new, ✓ for saved)
  2. Click session: Loads history and context into chat panel
  3. Chat suggestions: AI proposes next steps (chips: "Add condition", "Dry run", "Publish")
  4. Resize handle: User drags to balance chat ↔ context visibility
Resize Handle & Layout Lock
Resize handle between chat and context panel is always visible (when Stage 2+). Position persists in localStorage. Double-click handle to snap to preset widths (50/50, 60/40, 70/30).
.resize-handle { position: absolute; width: 4px; cursor: col-resize; z-index: 10; background: var(--border-light); } .resize-handle:hover { background: var(--primary); box-shadow: 0 0 8px var(--primary-soft); }
4. AI Interaction Patterns
How Claude and the user collaborate to build and refine flows. Patterns for suggestion, disagreement, and rehearsal.
Welcome → Session Start
User enters. Kalcifer shows brief intro. On first message, smooth fade/slide transition to Stage 1 (chat appears, sidebar slides). Subtle "Welcome back!" if returning.
Chat Suggestions (Chips)
After each Claude message, show 2–4 suggestion chips below. Examples: "Add email action", "Set frequency cap", "Run dry run". Click to populate input. Chips are context-aware and update as flow evolves.
Suggestion Chip Example
+ Add send_email + Add condition ▶ Dry Run
Canvas Builds from Chat
As user describes flow in chat, AI generates or updates canvas in real-time. User sees drag-and-drop nodes, edges, and labels materialize. No modal → canvas is always visible in context panel.
AI Disagreement / Clarification
If user's request conflicts with flow logic or best practices, Claude flags it: "⚠ Frequency cap after email will skip most users. Suggest moving to beginning." User can accept, reject, or ask for refinement. Visual diff shows proposed changes.
Dry Run as "Rehearsal"
Before publishing, user triggers Dry Run. Flow nodes get animated badges (▶ running, ✓ completed, ⏸ waiting). Timeline shows which node fires when. Cancellable mid-run. Results feed back to canvas and chat.

▶ trigger → condition ✓ send_email ⏸ wait
5. Canvas Editor Patterns
How flows are built and edited: toolbar, palette, node placement, zoom, and simulation.
Toolbar → Canvas → Footer
Top toolbar has zoom, pan, and layout controls. Canvas is center stage. Footer shows selected node details and quick actions (delete, duplicate, edit config).
Toolbar: [+] [Zoom] [Layout] [Simulate]
Canvas with draggable nodes
Footer: Selected node details
Node Palette (Slide-In)
Clicking [+] slides palette in from right. Categorized: Triggers, Conditions, Waits, Actions, Ends. Drag node to canvas. Palette stays open for rapid multi-add, or close after one drag.
.palette { position: fixed; right: 0; top: 0; width: 260px; height: 100%; background: var(--surface); transform: translateX(100%); transition: transform 0.3s; box-shadow: -2px 0 8px var(--shadow-lg); } .palette.open { transform: translateX(0); }
Node Config Panel (Replaces Palette)
Click a node on canvas or in palette → config panel slides in (replaces palette). Shows node-specific settings: channel (email/sms), template, retry logic, etc. Back button to palette.
Drag-and-Drop Nodes
Nodes have drag handles. Drag from palette to canvas, or drag existing nodes to reposition. Snap-to-grid optional. Edges auto-route; no overlapping lines.
// Node drag with ghost preview node.addEventListener('dragstart', (e) => { const ghost = node.cloneNode(true); ghost.style.opacity = '0.5'; e.dataTransfer.setDragImage(ghost, 0, 0); });
Zoom Controls & Pan
Mouse wheel zoom (Ctrl + scroll). Toolbar buttons for zoom presets (100%, Fit All). Pan with spacebar + drag or middle mouse button.
Simulation Flow & Badges
During dry run, nodes get animated status badges: ▶ (running), ✓ (completed), ✗ (failed), ⏸ (waiting). Edges highlight in sequence. Timeline sidebar shows which node fires when.
6. Responsive Stage Transitions
How layout adapts to screen size and user behavior. Collapsing sidebar, compressing chat, handling mobile.
Sidebar Collapse in Context Mode
In Stage 3, sidebar narrows to icon-only (~50px). Hover reveals labels. On mobile, sidebar hidden by default; hamburger toggles it as overlay. Stage reverts to 2.5 on mobile.
/* Desktop: sidebar always visible */ @media (min-width: 1200px) { .sidebar { width: 200px; } .sidebar.collapsed { width: 50px; } } /* Mobile: sidebar as overlay */ @media (max-width: 768px) { .sidebar { position: fixed; z-index: 100; transform: translateX(-100%); } .sidebar.open { transform: translateX(0); } }
Chat Area Compression
As context panel expands, chat shrinks. Below ~400px width, chat becomes vertical stack of messages (no columns). Input stays at bottom.
Resize Handle Behavior
On mobile, resize disabled (pinch to zoom instead). On tablet, resize appears but snaps to grid (25% increments). Desktop: smooth continuous drag.
Canvas on Mobile
Canvas editor becomes touch-friendly: larger tap targets, simplified toolbar, single-column palette. Pinch to zoom, two-finger pan. Geometry reflows to portrait orientation.
